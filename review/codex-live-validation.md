# 真实 Codex 验证与产品判断

日期：2026-11-08。基于交接提交 `d9cf1ce80a2d571df9fdc2d2259599cef0ec9b82`。开始及收尾均获取远端状态；仓库已更名为 [Ben-cpy/BOOK](https://github.com/Ben-cpy/BOOK)。

## 当前结论

**自动维护知识边界的主链路已经跑通，可以开始实际试用；不能据此宣称模型能准确测量用户的理解。** 本次验证了它在自然对话中的具体决策、跨会话记忆及错误恢复，也保留了尚未解决的解释偏长问题。

最终模式是全局安装 Skill/Hook，按当前项目独立维护 `.know/map.md`。安装从空地图起步，测试案例不会自动变成用户已掌握知识。

## 环境与证据标准

- Windows，Codex CLI **0.164.0**，Python **3.9.13**；默认 `python` 实际为 3.7.13，因此文档明确使用 `py -3.9` 或更高版本。
- 使用用户已有的模型服务配置，配置模型为 **gpt-6-astra**，测试推理强度 `low`。没有替换凭据或升级 Codex。CLI 提示有较新版本，本次没有将未测试版本写成已支持。
- 普通 `codex exec` / `exec resume` 真实调用模型；三个独立 Agent 扮演不同用户，自主设计追问。不是把预先准备的候选地图当成模型行为。
- 前期单项目试验用经审阅的 Hook 信任绕过参数和透明观测脚本。另用真实 CLI 界面验证项目授权、Hook 审阅与持久化信任；全局隔离试验不带绕过参数。
- 判断链路成立需要同时看到：UserPromptSubmit 的注入、模型写本轮候选、Stop 运行前后正式地图变化。跨会话还检查模型是否用到了新问题未提供、但地图中存在的具体知识边界。

配置位置、事件字段、`additionalContext`、`decision: block` 与信任流程对照了[官方 Hook 文档](https://learn.chatgpt.com/docs/hooks)，再在当前 CLI 上实测。`stop_hook_active` 在实际修复续答中从 false 变为 true，`session_id` 与 `turn_id` 保持不变。实现不解析 Codex 的不稳定 transcript 格式。

## 真实发现的问题及修复

| 问题 | 实际影响 | 修复 |
|---|---|---|
| 直接导入 `fcntl` | Windows 连测试导入和安装都失败 | POSIX/Windows 分别使用 OS 文件锁，补 UTF-8 与路径处理 |
| 只注入抽象规则，没有准确语法 | 第 2 轮候选缺 `##` 标题，Stop 触发修复，回答出现维护播报 | 把必要格式规则放进被注入的 Skill；普通保存不播报 |
| 同一 matcher 组中移除整个组 | 重新安装可能删掉组内其他 Hook | 只替换本集成的 handler，保留其他 handler 与组元数据 |
| 中断候选、二次失败残留 | 临时文件生命周期不完整 | 按会话/轮次隔离；成功、放弃和重复失败清理；恢复同一会话清理旧轮次 |
| 全局与本地共存 | 重复注入；若仅按配置存在让路，还可能两边都不工作 | 在同一地图锁内按实际本轮快照去重 |
| 双 Stop 遇到并发冲突 | 第二次 Stop 误删首个 Stop 留下的重试基线 | 保留一个临时 retry 标记；修复完成或放弃后一起清理 |
| 可发现的全局 Skill 与 Hook 同时加载 | 额外播报技能名、重复读取 | 全局规则放专用运行目录，只通过 Hook 注入 |
| 讲通因果后又重复图、公式 | 对略懂用户仍讲得过长 | 两轮收紧解释规则；同题最终回答 809→598→500 字符，仍未稳定达到“一段几句话” |
| Windows Git 换行转换 | README 的示例校验命令失败 | Markdown 使用 LF Git 属性，保留校验器的明确格式约束 |

长度数字来自单次定向复测，不是统计收益，也不是越短越好；复核时仍要求前层注意力→隐藏表示→后层 KV 的因果完整。

## 剩余限制与使用建议

1. **认知判断仍有误差。** 正确表述可能来自照抄，继续任务也不保证真懂。测试证明能在发现反证后纠正，没有证明长期准确率。
2. **简洁程度不稳定。** 冗余已经减少，但部分回答仍偏长；这比“能不能生成合法 Markdown”更需要真实用户反馈。
3. **正常更新安静，异常不保证无感。** Stop 修复会引发模型续答；本次并发注入测试就出现过重复业务答案。
4. **项目边界有明确规则。** Git 用仓库/worktree 根；非 Git 第一次应从项目根启动。每个项目默认一个主要用户，尚无多人身份隔离。
5. **并发保证有边界。** 锁协调本集成的写入，外部编辑器不参与锁；永不恢复的中断会话可能留 staging，确认结束后可删除。

本机已安装最终全局运行包并完成 CLI Hook 信任。日常从实际项目启动 `codex -C <项目路径>` 即可；首次输入后应看到该项目的 `.know/map.md`。新机器按 README 运行 `install.py --global`，然后审阅 `/hooks`。从真实项目连续使用几轮，重点审阅“解释是否恰好接上”和“记录是否过宽”，比继续增加格式测试更能判断产品价值。
