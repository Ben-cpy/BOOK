# 独立角色试用：新会话继承与误判纠正

这是测试 Agent 扮演用户、驱动真实 Codex CLI 的试用记录，不是真实用户验收。原行为案例的“待审批”状态未改变。

**结论：本轮 5 次真实模型调用中，地图跨会话生效；话题切换没有产生掌握记录；用户指出误判后，地图删除对应子节点并保留其他已知边界。** 没有出现格式重试、维护提示或残留候选文件。本轮没有发现需要修改产品代码的故障。

## 测试条件

- 独立临时 Git 项目 `cognition-transfer-1v2xbtkp`，从空 `.know/map.md` 开始。
- Codex CLI 0.164.0，Windows，Python 3.9；继承本机模型配置 `gpt-6-astra`，测试驱动设置 `reasoning_effort=low`。
- 实际调用 `codex exec` / `codex exec resume`，没有把期望回答或候选地图交给模型。
- Hook 观测包装器原样转发输入与输出，仅记录 `session_id`、`turn_id`、Hook 输出及地图前后内容。
- 经审阅的临时 Hook 使用单次 `--dangerously-bypass-hook-trust`；没有验证交互式 `/hooks` 的信任点击流程。
- 第一会话：`01a1baee-cea8-7482-aac3-88d54d58b316`；新会话：`01a1baf0-2117-72f0-a525-e2859d85af6e`。新会话没有恢复第一会话历史。

## 对话与实际结果

| 轮次 | 用户行为与关键输入 | 实际回答 | 实际地图结果 |
|---|---|---|---|
| 1 | “九成订单都是 completed，查 completed 却没走索引……为什么优化器宁愿全表扫描？” | 用“查目录 → 按位置取完整数据 → 读取九成记录可能比顺序扫描更贵”解释因果链。 | 仍为空。没有把刚讲过的内容登记为掌握。 |
| 2 | 正确应用上一轮：“先不强制……九成记录……到表里取其他列……千分之一 pending 更期待索引有收益。”再问 `SELECT status` 与 `SELECT *` 的差别。 | 连接已有的取其他列成本，解释覆盖索引如何改变成本；没有重新展开全表扫描基础。 | 加入“成本比较”及两个窄子节点；没有加入新问的“覆盖索引”。 |
| 3 | **新建会话**，只问 `(customer_id, created_at)` 与反过来的排列为什么影响扫描量。 | 解释“先聚集到同一客户再顺序取 20 条”与“按全局时间扫描并过滤”的差别；主动连接已有的回表知识。 | 原样保留；未把新讲的联合索引顺序记为掌握。 |
| 4 | “先放下查询问题……评审记录放 docs/reviews/ 下，文件名怎么起？只建议一个名字。” | 只返回 `docs/reviews/2026-11-09-order-index-review.md`。 | 原样保留；没有因不再追问而新增知识。 |
| 5 | “之前说‘索引之后还要到表里取其他列’其实是在照抄……不懂回表……选择性高低和该不该强制索引，我能判断。” | 接受纠正，用 InnoDB 的二级索引与主键索引解释回表；把覆盖与索引字段顺序分开讲。 | 删除“回表读取其他列的额外成本”，保留选择性相关知识；没有把本轮重新讲解的回表记回去。 |

第三轮最有辨识度的实际回答是：

> 你已经考虑过回表成本，这里还要区分……能在索引里过滤，不代表能直接跳到匹配记录所在的位置。

第三轮用户消息没有提回表，且使用不同 `thread_id`。该已知边界存在于 UserPromptSubmit 注入的地图中。这是模型在新会话中使用地图的具体证据，而不仅是 Hook 返回成功。

## Hook 证据与边界

5 次 UserPromptSubmit 与 5 次 Stop 全部退出码为 0。第二、五轮均观察到模型写入指定 `candidate.md`，随后 Stop 的 `before` 与 `after` 发生上述变化；其他轮次 Stop 返回 `{}` 且地图不变。未出现 `decision: block`，全部 `stop_hook_active=false`，最终 `pending/` 为空。正常回复没有提及地图、候选文件或“保存成功”。

原始 `t1`–`t5` JSONL、每轮 prompt、地图快照及 `hook-events.jsonl` 留在上述本机临时项目中；本报告保留可审阅的关键证据，不提交机器路径与整段运行日志。

本轮也说明一个语义限制：**模型不能可靠区分“理解后的正确表达”和“照抄出的正确表达”。** 第二轮把回表成本当作已掌握，在当时输入下是合理推断；第五轮才有反证，随后成功收缩。地图应被视为可修正的解释起点，不能作为用户能力证明。

这轮只验证一种模型配置、一个数据库场景、两段会话。它没有证明所有场景都能省讲，也没有验证长时间遗忘、模型切换或团队多人共用项目。联合索引和回表回答仍然较长，因此“自动适配”不等于保证简短；但本轮长回答集中在用户新问的机制，没有重讲已经登记的选择性基础。
