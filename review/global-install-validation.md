# 全局安装、项目级记忆：真实验证

日期：2026-11-08。Windows、Codex CLI 0.164.0、Python 3.9.13，配置模型 `gpt-6-astra`，测试推理强度 `low`。

**结果：全局运行包只放规则和脚本，A/B 项目分别保存自己的地图；新会话能够使用本项目的地图。** 本轮还发现并修正了全局安装引起的重复技能播报。

## 最终安装方式

```text
~/.codex/hooks.json
~/.codex/cognition-runtime/adapt-project-explanations/
    SKILL.md
    scripts/
    references/

<A>/.know/map.md
<B>/.know/map.md
<C>/.know/map.md
```

运行包放在专用目录，Hook 每轮注入完整 Skill；不额外放进自动发现的 Skill 目录。安装器没有创建全局知识地图，也没有把示例知识导入项目。

已实际执行两次全局安装，并在真实 CLI 启动界面审阅、信任两个 Hook。路径调整后重新审阅了新定义。下列 5 次模型交互**没有使用 `--dangerously-bypass-hook-trust`**，依赖已持久化的 Hook 信任；测试驱动仅为各临时项目提供项目信任配置。

## 五次实际交互

A/B/C 都是本次新建的独立临时 Git 项目，没有 `.codex/hooks.json`，没有调用单项目安装器。第一次启动前也不存在 `.know`。

| 交互 | 输入与行为 | 实际结果 |
|---|---|---|
| A1 | 正确解释 APC 的 TTFT 收益，控制并发与排队，继续设计长短前缀对比 | A 自动创建地图并记录推理性能知识；B 尚无地图 |
| B1 | 声明知道表由行列组成，首次询问索引的查找收益与写入成本 | B 的初始注入为空；只记录用户明确知道的行列概念，没有导入 A 的知识，也没有把刚讲的索引写成掌握；A 字节不变 |
| B2 | 自然应用索引定位与额外维护成本，判断低频查询是否值得加索引 | B 新增索引成本及其子节点；A 字节不变 |
| A2 | 新开会话，问“命中比例提高但 TTFT 变差，应先看哪些变量” | 回答连接 A 地图里的“单并发无排队”边界；A 地图不变，B 字节不变，无数据库知识混入 |
| C1 | 在全新项目首次询问索引为什么影响查找与写入，不声明已知知识 | Hook 创建空地图；解释后仍只有 `# 已掌握`，没有抢记新讲内容 |

A2 的新会话没有恢复 A1 的对话历史，用户新问题也没有提单并发。回答中出现：

> 若仍是之前的单并发无排队实验，先确认实际排队时间接近零……

这一具体边界只存在于 A 的地图，是使用项目注入内容的证据。没有把“回答专业”或“Hook 退出成功”单独当作地图生效证据。

## 实测暴露的问题与迭代

第一版把包放在 `~/.agents/skills`。A1、B1 中，Codex 除了收到 Hook 注入，还自动选择同名 Skill，播报正在使用技能并重复读取文件。A1 的额外 PowerShell 读取甚至使用了错误的中文解码；正确的 Hook 注入仍然工作，但这不是理想的无感体验。

改为专用运行目录后，B2、A2、C1 没再播报 Skill 名称或地图维护，也没有额外读取旧 Skill 路径。B2 保留旧会话历史，A2/C1 则是新会话，覆盖了两种情况。这验证了此次修复，不能证明所有模型永远不会提及内部机制。

另外，本地与全局 Hook 的共存通过实际执行幂等控制，不根据“本地配置是否存在”猜测它是否已启用或信任。这样本地 Hook 被跳过时，全局 Hook 仍可工作。
