# vLLM KV cache · One-shot 案例审阅

四个案例均为合成对话。A 和 C 已按审阅意见修改。整组案例供审阅，获批后可作为 Skill 的行为示例。

## A · 同一边界反复卡住 → 补一段因果桥

**初始地图**为空。先前在 s01:t02，用户问系统提示变化后能否复用相同文档，助手解释了前缀匹配。审阅新请求时，用户又在 s01:t04 问：「开头换了，但后面的文档完全相同，能从文档中间重新命中吗？」

**理想回答**：「可以把两次请求想成 `A → 文档` 和 `B → 文档`。在自回归模型里，文档中的每个位置都能看到它之前的 token。A 换成 B 后，文档字面虽然一样，它在后续层算出的 KV 仍可能不同。vLLM 因此把上游前缀也算进块的身份，只复用仍一致的前缀。分叉后的那段文档要重新计算。」

**地图变化**：在「前缀复用」下新增一条边界，解释留在回答里。

```markdown
- [补桥] 开头变化后相同文档能否接续命中 <!-- prefix-match | repeated | s01:t02, s01:t04 -->
```

## B · 讲过以后，在同类任务中继续往前 → 省掉提示

**初始地图**：「命中对首 token 与后续生成延迟的影响」标为补桥。助手在实验审阅里补过一次「前缀复用省的是输入处理，新 token 仍要逐步生成」。

**自然对话**：用户在 s01:t06 说「把长输入和短输入分开列 TTFT 和 TPOT。」又在 s01:t08 说「输出长的那组，给我看命中前后的 TTFT 和 TPOT 各差多少。」两次都在处理同一个延迟边界，并直接推进分析。

**理想行为**：给出同组的两项差值。示例没有测量值，可以说明需要命中与未命中的同组数据。将原边界标为「可直接讲」，来源为两次相关后续使用机会。下次同类审阅直接给结果。若以后在这一层重新卡住，则恢复补桥。

## C · 父节点已懂，问题下钻 → 新增一层

**初始地图**：「前缀一致性与连续命中」已标为可直接讲。用户在 s01:t04 问：「开头一致我懂了。如果这份文档结尾只填了半个块，这半块能作为下一次的命中吗？」

**理想回答**：「按标准 vLLM V1 APC 路径，当前请求可以使用已算出的这半块 KV。跨请求复用按完整块命中，所以这半块还不能独立命中。」

**地图变化**：该区别会影响下一次审阅命中 token 数。新增一个子边界，保留父节点。

```markdown
- [可直接讲] 前缀一致性与连续命中 <!-- prefix-match | used | s01:t02 -->
  - [待厘清] 未填满的块能否跨请求复用 <!-- partial-block | frontier | s01:t04 -->
```

## D · 话题切换 → 地图保留

**初始地图**：「命中对首 token 与后续生成延迟的影响」标为补桥。助手刚用过这条桥。

**自然对话**：用户说「先不看 TTFT 了。下个实验换一份请求 trace，文件放哪里比较合适？」

**理想行为**：回答 trace 的组织问题，保留这条地图记录。这次任务没有用到 prefill 和 decode 的区别。
