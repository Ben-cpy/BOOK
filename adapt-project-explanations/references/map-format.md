# Map and hook contract

The [sample map](map.example.md) is illustrative. Installation creates an empty map.

The first line is exactly `# 已掌握`. Topic headings start with `## `. Knowledge labels are plain Markdown bullets, using two spaces per nested level. A parent must exist before a child. Headings and labels are at most 80 characters, depth at most four levels, and the entire map at most 60 entries and 16 KiB. Use UTF-8 without BOM, LF and a final newline. Duplicate siblings, bracketed tags, angle brackets, pipes, empty topics and broken indentation are rejected. The validator enforces syntax and size; it cannot determine whether a plain-text label is really understood or is a disguised definition, score or status. The Skill governs those semantic decisions.

The Skill and hooks may be installed globally, but the project root always determines memory scope. There is no global knowledge map. In global mode the adapter resolves `cwd` to its Git repository/worktree root. Outside Git, it uses the nearest existing project map, otherwise the current directory (except a bare user home or filesystem root). Start non-Git projects at their intended root for first use. Runtime files stay in that project's `.know/`.

- `map.md` contains the current understanding tree.
- `pending/<session hash>/<turn hash>/` contains a base snapshot, an optional candidate, and a temporary `retry` marker while reconciling a conflict. The marker prevents a second enabled Stop handler from deleting the refreshed baseline before the model can repair it. Successful, unchanged and twice-invalid updates are cleaned up. The next prompt in the same session discards its interrupted turn's staging without touching other sessions. If a session is never resumed, its staging remains until deleted after that session has ended; it is never automatically committed.
- `map.lock` serializes updates made through the hook.

`UserPromptSubmit` creates an empty map on first use, then injects the Skill, format rules, project scope, current map and absolute candidate path as `hookSpecificOutput.additionalContext`. It captures a snapshot for that session and turn. Under the map lock, an existing snapshot makes a duplicate submission a no-op; this also prevents double injection when current global and project hooks both execute. No inference about another hook's trust or enablement is needed. `additionalContextLimit: 0` keeps the bounded map from being spilled or truncated by Codex. `Stop` validates an optional candidate and atomically replaces the map if the base still matches. Identical content is not rewritten. A concurrent change causes one retry against the new map. The stale candidate is discarded, so an accidental duplicate Stop cannot apply it. Repeated validation failure leaves the live map untouched, removes staging and reports the problem. A Stop repair can produce an additional model response; normal successful/no-update turns produce no maintenance message.

`install.py --global` copies the Skill, scripts and references into `<CODEX_HOME>/cognition-runtime/adapt-project-explanations` and merges two handlers into the user's Codex `hooks.json` (`CODEX_HOME`, default `~/.codex`). This runtime is deliberately outside automatic skill discovery: the hook already injects the complete Skill, so registering it again caused redundant reads and skill-use announcements in real tests. No project memory is created by global installation. The copied runtime survives moving the cloned repository; rerun the installer to update it. `--codex-home` and `--runtime-dir` allow isolated installation tests without changing environment variables (`--skills-dir` is an alias for the runtime parent).

`install.py --project ROOT` retains the original project-only installation and immediately creates its empty map. It references the cloned scripts, so keep that repository at its installed path or reinstall after moving it. Both modes preserve unrelated handlers, even in a shared group, and back up original configuration once. Global mode also backs up a pre-existing installed Skill once outside the discoverable skills directory. Update older project-only installations before combining them with global mode.

Codex requires trust for hook definitions; project-local configuration also needs project trust. Review at startup or through `/hooks`. The installer does not grant trust. Test automation can use the CLI's per-invocation hook-trust bypass after reviewing the code; ordinary use should persist trust through the UI.

The adapter targets Codex CLI hook events with `session_id`, `turn_id`, `cwd`, and `hook_event_name`. `Stop` additionally uses `stop_hook_active` to prevent repeated repair loops. JSON arrives on stdin; the script emits UTF-8 JSON on stdout. `decision: block` asks Codex to continue to repair the candidate; `{}` allows stopping. No transcript parsing is used.

Python 3.9+ is required. Windows uses an OS byte-range lock and an explicitly invoked PowerShell command; Linux/macOS use `flock` and shell quoting. Windows paths with spaces and Chinese characters are tested. OS locks are released if a process dies. The scope guard ignores other projects and nested independent Git/installed projects. The model remains responsible for the meaning and scope of an update. Locks serialize cooperating hooks; they cannot prevent an editor or another tool from directly writing the live file during a save.

Verified in Windows Codex CLI 0.164.0 with configured `gpt-6-astra`. Other Codex versions and Linux/macOS have not been exercised in this verification run.
